Act 1: Bad Test Patterns

The hidden time sinks

  • Delay Real async delays — Future.delayed(seconds: 3)
  • Setup Heavy setUp — setUp(() async { await Future.delayed(500ms) })
  • Parallelism Mega test files — 30+ tests in one file
  • Rendering Excessive pumping — 100x pump loops
  • I/O Real disk writes in tests

The Worst Offender

// Looks innocent... but waits 3 REAL seconds
test('should debounce search input', () async {
  cubit.search('query');
  await Future.delayed(const Duration(seconds: 3));
  expect(cubit.state, isA<SearchSuccess>());
});

// x 198 tests across 4 packages = 594 seconds of waiting

Act 1 Result Reveal

// Just await the action directly
test('should debounce search input', () async {
  await cubit.search('query');
  expect(cubit.state, isA<SearchSuccess>());

Act 4: CI-Level Optimizations

Stop duplicating work

  • DUP Running pub get per package per CI job
  • DUP Running dart analyze per package
  • WASTE Full native build when only Dart changed
  • WASTE Testing all packages when one changed

Selective Mobile Builds = Huge Cost Win

Most PRs are Dart-only, but full native builds still run

Every commit
Android ~20 min
iOS ~20 min
~40 native build minutes per commit
→
Dart-only PRs
Use dart snapshot path
Skip full Android + iOS rebuilds
Build native only when inputs require it
# Decision gate
if: pubspec.lock changed OR android/ changed OR ios/ changed
  -> run full mobile builds
else
  -> run flutter build bundle (fast Dart snapshot path)

Example impact: with 30 PRs/day and 80% Dart-only changes, skipping ~40 min/PR saves about 16 runner-hours/day.

The Fix: Workspace-Level Resolution

# .github/workflows/pr_check.yml
setup:
  steps:
    - run: dart pub get              # ONCE at root
    - uses: actions/cache@v4         # cache .dart_tool
      with:
        key: pub-${{ hashFiles('**/pubspec.lock') }}

analyze:
  steps:
    - run: dart analyze .            # ONCE for workspace

test:
  strategy:
    matrix:
      package: [app, core, payments, analytics]
  steps:
    # Restore cache — no pub get needed
    - if: needs.setup.outputs.affected
      run: flutter test

Key Takeaways

  • 1 Fix your tests first — async delays, heavy setUp, real I/O
  • 2 Parallelize across packages — simple shell script
  • 3 Bundle tests — reduce isolate cold start overhead
  • 4 Cache pub get at workspace level
  • 5 Analyze once at workspace root
  • 6 Test selectively using dependency graph
  • 7 Build selectively — skip Android/iOS rebuilds for Dart-only PRs
  • 8 Diff coverage — measure only what changed
